## Вход по заявке — гейт на этапе закрытого тестирования (2 сентября 2026)

Просьба владельца: «как в Автопосте» — посетитель без входа видит вместо сайта
блок «Войти / Запросить доступ», заявка уходит владельцам в Telegram, вход
открывается после одобрения. «Потом уберём» — поэтому всё собрано так, чтобы
снять одной строкой.

- **Включить/выключить:** `ACCESS_GATE` в `main.py` — `os.environ.get(
  "ACCESS_GATE", "1") == "1"`, по умолчанию ВКЛЮЧЕНО (на Timeweb переменной
  нет — гейт работает). Выключить: `ACCESS_GATE=0` в окружении боевого хоста
  или поменять умолчание `"1"` на `"0"` в одной строке. Гейт визуальный: API
  сделок и компаний не закрываются, закрыт только вход в аккаунт.
- **Что делает сервер.** `/api/me` отдаёт `gate` (и `approved` для вошедшего);
  `POST /api/auth/register` при включённом гейте создаёт `User.approved=False`,
  НЕ ставит сессию, отвечает `{"ok": true, "pending": true}` и шлёт заявку в
  консоль (`_notify_access_request`: `_review_chat_ids()` + `tg_api`, кнопки
  `acc:<user_id>:ok|no`; сбой Telegram регистрацию не роняет); `POST
  /api/auth/login` для неодобренного — 403 с `GATE_PENDING_TEXT`. Одобрение —
  ветка `acc:` в `telegram_webhook` рядом с `mod:`: право по `from.id`
  (`_is_reviewer`), решение пишется ПРЯМО в `users` (аккаунты живут в базе
  сайта, рутина не нужна), штамп в сообщение через `_mark_decided`
  (`acc_ok`/`acc_no`). Отклонённый остаётся с `approved=False`: повторная
  заявка тем же адресом — «уже зарегистрирована», дубля нет.
- **Миграция.** `_ensure_user_columns(engine)` в `main.py` (вынесена из
  стартового хука) добавляет `approved` через инспектор SQLAlchemy и ставит
  `True` всем уже существующим аккаунтам отдельным `UPDATE` с параметром
  (не `DEFAULT TRUE`/`DEFAULT 1` — литералы расходятся между SQLite и
  Postgres). Тест на «старой» таблице —
  `test_users_table_created_before_the_gate_gets_approved_column_set_to_true`.
- **Экран.** `renderGate()` в `static/index.html`: `GATE`/`gated()` рядом с
  `ME`; `route()` до первого ответа `/api/me` не рисует ничего (иначе сайт
  мелькает перед дверью — `refreshMe()` сам зовёт `route()` после первого
  ответа), при закрытом гейте рисует гейт и НЕ перерисовывает его на
  повторных вызовах (смена хеша, приход базы) — форму нельзя стирать; адрес
  при этом сохраняется, после входа тот же `route()` открывает его. Шапка и
  футер остаются; `updTop()` считает гейт «не главной» (светлая шапка).
  Общий `authRequest()` обслуживает и гейт, и экран «Аккаунт».
- **Тесты.** `conftest.py` ставит `ACCESS_GATE=0` для всех тестов;
  тесты гейта включают его через `monkeypatch.setattr(main, "ACCESS_GATE",
  True)` (`test_accounts.py`) или вторым сервером `gated_url` с `ACCESS_GATE=1`
  (`test_ui.py`, один сквозной тест). Урок из этого теста: `page.goto` на ТОТ
  ЖЕ адрес с тем же хешем — переход по фрагменту, страница не
  перезагружается и состояние формы остаётся; для чистого старта нужен
  `page.reload()`.
- **Страховка от потерянной заявки — шаг прогона публикации.** Уведомление
  о заявке шлёт сам сайт, и его сбой регистрацию НЕ роняет (заявка важнее
  уведомления) — значит, заявка может лежать на сайте, а в консоли о ней
  никто не узнает; человек будет ждать доступа молча. Каждый прогон
  публикации вызывает `python3 pipeline/send_access_requests.py --write`:
  он берёт ожидающих через тот же `/api/access/requests?token=…` и шлёт по
  каждому сообщение с кнопками «Одобрить»/«Отклонить». Показанное помнится в
  `pipeline/access_requests_sent.json` (в git), поэтому почасовой шаг не
  превращается в ежечасное напоминание об одной и той же заявке; повторить
  вручную — `--again`. Id для кнопок берётся ИЗ ОТВЕТА БОЕВОГО САЙТА: 4
  сентября 2026 кнопка с id из локальной базы одобрила на проде совсем
  других людей.
- **Что не сделано.** Письма заявителю не шлём (SMTP нет) — экран честно
  говорит «вход по этим данным заработает, обычно в течение дня». Когда гейт
  снимут, `approved` можно оставить: он ни на что, кроме гейта, не влияет.
