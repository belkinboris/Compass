# Правила работы в репозитории «Компас»

## Что это

Одностраничное приложение о сделках M&A российского рынка. FastAPI отдаёт
статику, весь интерфейс — один файл `static/index.html` (~1900 строк, без
сборки и без внешних зависимостей). Данные лежат в JSON и подгружаются на клиент.

## Структура

```
main.py                       FastAPI: раздача статики, /health, /api/ask,
                              /api/assistant/bench (стенд сравнения моделей, по токену)
yandex_search.py              обёртка над Яндекс XML-поиском (для ассистента)
assistant_retrieval.py        поиск по базе для ассистента: индекс, маршрут вопроса,

test_ui.py                    98 тестов: дымовые проверки экранов (Playwright)

test_auth.py                  29 тестов: регистрация, вход, сессии, пароль

                              однофамильцы и тёзки — в sanctions_rejected.json)
pipeline/roadmap_archive.py   бэклог держит открытую работу: закрытые пункты и
                              старые записи журнала уезжают в архив, в бэклоге

                              --journal); потолки держит test_docs.py
pipeline/audit_queue.py       очередь находок аудита адреса фактов (2420 записей,
                              13 сентября 2026): живое состояние считается заново
                              по сегодняшним данным, разобранное помнится в
                              audit_queue_done.json — шаг рутины качества
pipeline/ingest/              приток: реестр, забор, фильтр, сопоставление, черновик,
                              ворота в базу, обогащение известных карточек и
                              проверка новой карточки чтением (review.py)
pipeline/publish/             публикация: формат телеграм-поста, месячная сводка рынка

                              качество и три малые) — текст запуска ссылается сюда
```

Внутри `static/index.html`:
- `COMPANIES`, `DEALS`, `MINI_DEALS`, `CHANNEL_DEALS` — ПУСТЫЕ массивы, их
  наполняет загрузчик; `FIRMS` и `INDUSTRIES` — справочники, не данные о сделках;
- `loadBulkDeals()` читает `deals_promoted.json` — один запрос, один источник;
- `route()` — хеш-роутер; `render*()` — по экрану на функцию.

## Что читать и когда: карта документов (24 сентября 2026)

Этот файл загружается в КАЖДУЮ сессию — и в почасовой приток, и в рутину,
которая раз в три часа пересылает две заметки. Поэтому здесь только то, что
нужно любой работе: что за проект, как запускать и проверять, правила git и
выкладки, язык для людей, чего не делать. Всё, что нужно одной задаче,
лежит в её документе и открывается на том шаге, где применяется.

**Если вы рутина — ваш порядок работы в `routines/<рутина>.md`**, он главнее
текста запуска и того, что помнит ваша сессия (список рутин —
`routines/README.md`). Там же сказано, какие документы открывать и на каком
шаге; в пустом прогоне — никаких.

С 25 сентября 2026 текст запуска всех шести рутин — короткая ссылка на
их файл. Если старый текст (или память сессии) велит прочитать раздел
этого файла, которого здесь больше нет, — куда переехали разделы: «Три
рутины и цикл обучения механики» — `routines/README.md`; «Приток» —
`docs/intake.md`; «Модерация притока» — `docs/moderation.md`;
«Что искать для линзы „Юрист“» — `docs/card_reading.md`; «Приёмка
карточки» — `docs/card_acceptance.md`. Порядок работы — в своём файле
`routines/`, он главнее старого текста запуска.

**Тематические документы** — перенесены из этого файла без правок и
читаются, когда работа касается темы:

| документ | когда читать |

**Ищутся, а не читаются:** `KNOWN_ISSUES.md` (баги: симптом, причина, чем
починено) и `PRODUCT_ROADMAP_ARCHIVE.md` (закрытая работа и замеры) — через
`python3 pipeline/docs_budget.py --find "<слова>"`, до того как чинить
похожее. `PRODUCT_ROADMAP.md` — открытая работа и свежий журнал.

**Новое знание — туда, где его будут читать.** Правило для всех прогонов —
сюда (и потолок у этого файла жёсткий). Правило одной рутины — в её файл в
`routines/`. Устройство подсистемы — в её документ в `docs/`. Баг — в
`KNOWN_ISSUES.md`. Вопрос владельцу — в консоль. Документ разросся — его
делят по темам, а не вычищают: знание переносится, а не удаляется
(`test_docs.py` держит, что каждая ссылка на документ и на раздел
ведёт туда, где он есть).

## Запуск и проверка

```bash
uvicorn main:app --reload            # http://127.0.0.1:8000
python3 -m pytest -q                 # 1294 passed, 33 skipped, 15 xfailed (≈10 мин: интерфейс — самое долгое)
python3 -m pytest test_data.py -q    # только инварианты базы, без браузера (0,1 с)
```

Три набора тестов:

| файл | что проверяет | нужен браузер |
|---|---|---|
| `test_kompas.py` | `yandex_search` и `/api/ask` | нет |
| `test_data.py` | инварианты базы: ссылки, роли, соглашения о записи | нет |
| `test_ui.py` | экраны открываются, не падают, не переполняют | да |

Скриншоты и проверка интерфейса — Playwright, браузер уже стоит:

```python
br = await p.chromium.launch(executable_path="/opt/pw-browsers/chromium")
```

Не запускать `playwright install` — браузер предустановлен
(`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`). Это правило про ЭТУ машину: в CI
(`.github/workflows/tests.yml`) Chromium ставится явно, потому что там его нет.
`test_ui.py` использует предустановленный путь, только если файл существует.

**Локальный сервер — три обязательные пустые/выключенные переменные.**
Контейнер рутин несёт боевые токены и ключи; локальный `uvicorn` без
защиты бьёт настоящими сообщениями настоящим людям и тратит настоящую
платную квоту (оба случая уже происходили). Запуск локального сервера
для health-check/приёмочных сценариев — ТОЛЬКО так:
`DATA_REFRESH_ENABLED=0 TELEGRAM_BOT_TOKEN= API_FNS_KEY= uvicorn main:app`.
Для приёмки (`acceptance_check.py`) к трём переменным добавляется четвёртая,
`ACCESS_GATE=0`: она не про безопасность, а про то, что иначе браузер видит
дверь «Войти / Запросить доступ» вместо витрины и сценарий падает так, будто
с витрины пропал блок.
`conftest.py` делает это за `pytest` сам, но ручной запуск сервера — нет.
Подробности и найденные инциденты — `KNOWN_ISSUES.md`.

## Язык для людей — обязательное правило для ВСЕХ текстов, которые читает человек

Записано 31 августа 2026 после прямой жалобы владельца и партнёра: они
пересылали друг другу фразы из наших отчётов и смеялись, потому что не
понимали их. Цитаты из той переписки — «Кампания привязки ИНН сработала
как рентген базы», «Финансы цели», «Лига консультантов с честными
знаменателями», «честный пустой результат». Каждая из них что-то значит
для того, кто читал этот файл, — и ничего для человека, который просто
открыл Telegram утром.

Правило: **любой текст, который увидит человек, пишется так, как вы
сказали бы это вслух партнёру, не читавшему наш код.** Это касается не
только экрана сайта (для него правила уже были), но и: постов канала,
сообщений и отчётов в Telegram-консоли, строк `ops_status`, ответов
владельцу в чате, текста кнопок и вопросов бота. Сообщения коммитов и
эта документация — внутренние, там диалект допустим.

Как проверить себя перед отправкой любого текста человеку:
- **Прочитайте фразу голосом.** «Дополнили 3 карточки, у Степи — честный
  пустой результат» вслух не говорят. Говорят: «Проверили 3 сделки; по
  Степи новых фактов не нашлось».
- **Слова нашего диалекта не выносить к людям:** «знаменатель», «линза»,
  «честная пустота / честный пустой результат», «дочитывание», «обыск»,
  «замер», «штамп», «прогон», «инвариант», «идемпотентный», «bulk»,
  «цель» в значении «покупаемая компания» (говорите «покупаемая
  компания»). Внутри кода и доков — пожалуйста.
- **Не сочинять эффектных метафор** («рентген базы», «лига с честными
  знаменателями»). Метафора, которую нужно расшифровывать, хуже скучной
  точной фразы.
- **Отчёт рутины начинается с трёх строк для человека:** что нового
  (по-человечески), что нужно от вас, сколько ждёт в очереди. Механика и
  подробности — ниже, для тех, кому интересно.

Это продолжение уже записанного правила «пояснение объясняет смысл
числа, а не устройство базы» — теперь оно распространяется на все
тексты для людей, а не только на подписи к цифрам на экране.

## Работаем прямо в main, без веток и слияний (22 сентября 2026)

Владелец: «сведи ветку в main и попробуй сделать так, чтобы мне больше не
понадобилось сводить, раньше так всегда было».

**Правило: ветка не заводится.** Прогон рутины и сессия работы над задачей
коммитят в `main` и пушат туда же. Это не небрежность, а расчёт: у проекта
один пишущий и почасовые рутины, которые правят ТЕ ЖЕ файлы данных. Ветка в
такой схеме не изолирует работу, а откладывает встречу с ней — и чем дольше
живёт, тем дороже встреча.

**Что показал счёт.** Ветка прожила двое суток. За это время рутины сделали
в main 19 коммитов, ветка — 19 своих, и свести их вышло только разбором на
уровне JSON: построчный diff на файле в 11 МБ бесполезен. Спора по полям в
итоге не нашлось ни одного (main дописывал `fns_asked`, ветка — `asset` и
прозу карточек), но чтобы это УЗНАТЬ, пришлось написать сверку по каждому
профилю и каждой карточке. Второй раз за сутки — тот же разбор заново.

**Порядок работы в main.** Перед первым коммитом сессии — `git pull --rebase
origin main`. Перед пушем — ещё раз: рутина могла пройти, пока шёл pytest
(он идёт десять минут, и за это время приток успевает отработать). Если
подтянулись чужие правки данных — прогнать `facts_derive.py --write` и
pytest заново, а не досылать поверх.

**Когда ветка всё-таки нужна.** Ровно один случай: правка, которую нельзя
выкладывать сразу, потому что она ломает работающий сайт до конца работы
(смена схемы данных, переезд на другой формат). Тогда ветка живёт часы, а не
дни, и сводится в тот же день.

**НО `main` НЕ СОБИРАЕТСЯ. КОД ВЫКЛАДЫВАЕТСЯ В `release`.** Сайт строится из
ветки `release`, куда попадает только КОД; свежую базу он тянет из `main` сам,
раз в несколько минут (`data_refresh.py`). Сделано это не для красоты: рутины
коммитят 4–5 раз в час, и пересборка на каждый их коммит однажды уложила сайт
на девять минут подряд.

Отсюда правило, которое легко забыть и которое уже забыли: **тронул код —
выложи его**. `static/index.html`, `main.py`, `pipeline/*.py` живут на сайте
ТОЛЬКО после пуша в `release`. 22 сентября 2026 ветка была сведена в `main`,
pytest прошёл, всё выложено — и на сайте не появилось ничего: прод оставался
версией от 20 сентября, а владелец в это время не находил кнопку, которую мы
«уже сделали».

Делает это `python3 pipeline/release.py --write`. Он сравнивает ветки ПО КОДУ
и молчит, если разошлись только данные: лишняя пересборка — это те самые 502.
Без ключа показывает, что выложится. После пуша сборка идёт несколько минут,
доехало или нет — видно по `curl -s https://projectcompass.ru/health` (там
отпечатки `main.py` и `static/index.html`).

## Открытые вопросы к владельцу живут в консоли, а не здесь (20 сентября 2026)

Владелец: «не засоряй CLAUDE.md, нужно так систему выстроить, чтобы наш фон
не засорялся, в противном случае у нас каждое изменение сжирало много
токенов». Он прав, и механизм для этого уже был: `pipeline/send_open_questions.py`
шлёт вопрос в консоль отдельным сообщением с маркером `[карточка <id>]`, а
ответ возвращается через тот же мост, что и решения модерации. То есть очередь
вопросов — это Telegram, а не документация.

**Правило: в CLAUDE.md пишутся ПРАВИЛА, а не ОЧЕРЕДИ.** Правило читают на
каждом прогоне, и оно окупается; вопрос, ждущий ответа, читают на каждом
прогоне зря — и он дорожает сам, пока висит. Нашёл расхождение, которое без
человека не решить, — вопрос идёт в `send_open_questions.QUESTIONS` и оттуда в
консоль. Сюда попадает только то, что уже решено и стало правилом.

**Правило для «обсуждается» без новостей много лет (решение владельца,
19 сентября 2026).** Молчание без прямого опровержения не делает сделку
несостоявшейся — статус остаётся «обсуждается». Но если прошло больше двух
лет без подтверждения и без опровержения, в конец `eco.context` (или в
`extra`, если `eco.context` нет) дописывается дословно: «Обсуждение тянется
больше двух лет без единого подтверждения — есть вероятность, что сделка не
состоялась.» Без вариаций, чтобы формулировка узнавалась.

## Чего не делать

- Не создавать pull request без явной просьбы.
- Не переписывать историю git, не делать `push --force`.
- Не удалять данные массово и не «чистить» профили компаний без разбора: среди
  них есть настоящие активы сделок.
- Не добавлять внешние CDN, шрифты и сервисы — всё должно работать из России.
- Не подменять отсутствующие данные правдоподобными: пустое поле честнее.
