# Ревизия базы — фаза 2, инструкция потоку

Читать ПОСЛЕ `READING_BRIEF.md` (общий порядок партии, границы, докстрока
партии — там же). Этот файл — только то, чем ревизия отличается от обычного
дочитывания.

## Зачем это отдельная фаза

Замечание владельца 10 августа: «вопрос не в том, чтобы источник новый в
карте показался. Мы должны всё прочитать, мы обязаны в карту добавить всё
из всех источников, которые есть по этой сделке». Цель — не факт в поле
«source count», а то, что в карточке лежит ВСЁ существенное, что вообще
есть в интернете про эту сделку.

Фаза 1 (обычное дочитывание) была нужна, чтобы у каждой карточки была хотя бы
честная базовая обработка одного источника, — это минимум, а не потолок.
Часть карточек фазы 1 прошли только с одним источником не потому, что второго
не существует, а потому что поиск делался нерегулярно (замер 10 августа: 2
успешных поиска из 521 карточки, пока правило не встроили в каждый часовой
перезапуск). Ревизия — целевой проход по именно этим карточкам, с более
настойчивым поиском, чем в фазе 1.

## Очередь ревизии

Карточки, у которых `reviewed` УЖЕ стоит, но источник ровно один — это не
брак фазы 1, это недоделанный потолок:

```python
import json
base = json.load(open('static/data/deals_promoted.json'))
def nsrc(c):
    return len([u for _l, u in (c.get('src') or []) if str(u).startswith('http')])
queue = [c for c in base['deals'] if c.get('reviewed') and nsrc(c) < 2]
queue.sort(key=lambda c: str(c.get('date')), reverse=True)
```

Берите свою партию так же, как в фазе 1 (свой год или диапазон, свой файл
`fixes/batch_<буква>_revN.py`).

## Чем ревизия карточки отличается от первого чтения

Карточка уже прочитана один раз — статья за карточкой уже в кэше, читать
заново её не обязательно (если только не пропущено что-то на первом
проходе — тогда стоит перечитать). Основная работа здесь — ПОИСК, и он
настойчивее, чем в фазе 1:

1. Не один запрос, а несколько под разными углами: `<стороны> <предмет>`;
   `<стороны> сделка закрытие`; `<стороны> согласование ФАС` (если карточка
   ещё идёт или недавно закрылась); `<стороны> юридический консультант`;
   `<предмет> оценка стоимости`. Цель — не первый совпавший результат, а
   ВСЁ, что относится к этой сделке: деловое издание, отраслевой канал,
   пресс-релиз одной из сторон, рэнкинг консультантов, при необходимости
   ЕГРЮЛ/картотека арбитражных дел для проверки исполнения.
2. Каждый найденный материал — по правилам READING_BRIEF («Заголовок против
   текста»): про эту сделку, а не про сторону вообще; скачан
   (`fetch_article_texts.py <адрес> --write`), а не взят на веру по
   пересказу поисковика.
3. Из ВСЕХ найденных источников — не только то, что закрывает пустые поля,
   но и то, что УТОЧНЯЕТ уже заполненные: другая (более авторитетная,
   например ЕГРЮЛ против журналистского пересказа) цифра, более точная
   формулировка предмета, факт, который меняет понимание уже написанного.
   `review.py` для повторной правки поля работает так же, как для первой —
   `old` = что стоит сейчас, `new` = уточнённое значение, обе версии по
   дословной цитате.
4. Если по всем запросам ничего сверх уже известного не нашлось — это
   честный итог, не провал. В докстроке партии — не только положительные
   находки, но и это: «g123 — три запроса, ничего сверх уже известного».

## Что считается законченной ревизией карточки

Не «нашли что-то новое», а «искали настойчиво и по всем углам, независимо от
результата». Карточка с одним источником, честно оставшаяся с одним
источником после трёх-четырёх разных запросов, — это тоже пройденная
ревизия, и от карточки, которую вообще не пытались обыскать, её отличает
только след в докстроке партии.

## Когда остановиться

Своя очередь ревизии пуста — короткий отчёт и стоп. Как и в фазе 1, не
переходить на карточки, за которые отвечает другой поток.
