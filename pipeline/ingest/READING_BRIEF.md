# Дочитывание базы — инструкция потоку

Короткий бриф ВМЕСТО чтения `PRODUCT_ROADMAP.md`. Роадмап — 145 тыс. знаков
(44 тыс. токенов) на каждый прогон; при четырёх потоках и полусотне прогонов
это два миллиона токенов, потраченных ни на что. Здесь — только то, без чего
нельзя читать карточки. `CLAUDE.md` загружается сам, его читать надо.

## Задача

Взять свою партию карточек, прочитать по каждой ПОЛНЫЙ текст статьи-источника
и перенести факты в поля карточки через `pipeline/ingest/review.py`. Ничего не
сочинять: каждое значение подтверждается дословной цитатой, и скрипт это
проверяет.

## Своя партия и свой файл

Поток работает с ОДНИМ годом (или указанным диапазоном) и пишет правки в
СВОЙ файл `pipeline/ingest/fixes/batch_<год>_<буква>.py` — один список `FIXES`
внутри. В чужие файлы не писать: на этом держится возможность читать в
несколько потоков одновременно.

Очередь своего года:

```python
import json, re
base = json.load(open('static/data/deals_promoted.json'))
year = 2024                                    # свой год
def y(c):
    m = re.match(r'^(\d{4})', str(c.get('date') or '')); return int(m.group(1)) if m else 0
queue = [c for c in base['deals']
         if y(c) == year and not c.get('reviewed')
         and any(str(u).startswith('http') for _l, u in (c.get('src') or []))]
queue.sort(key=lambda c: str(c.get('date')), reverse=True)   # свежие первыми
```

## Порядок одной партии (20–25 карточек)

1. `git pull origin main`
2. Очередь своего года: `python3 pipeline/ingest/read_card.py --queue 2024 25`
3. `python3 pipeline/ingest/fetch_article_texts.py <20–25 id> --write`
   Замер: ~2 с на адрес, у 15% карточек ни один источник не отдаёт текст —
   это нормально, такие пропускаем (не помечаем прочитанными, они уйдут в
   отдельную задачу о вторых источниках).
4. `python3 pipeline/ingest/read_card.py <id> [<id> ...]` — печатает поля
   карточки и тело статьи без навигации. Читайте ТОЛЬКО через него, партиями
   по 4–6 карточек за вызов. НЕ открывайте `data/inbox/raw/*.jsonl` целиком:
   файлы по 300 КБ и больше, у изданий 60–80% выгрузки — меню и «читайте
   также», и всё это потом перечитывается на каждом ходу. Замер кампании
   9 августа: 615 тыс. токенов на карточку вместо ~4 тыс. на саму работу,
   то есть 99% денег ушло на перечитывание навигации.
5. Пишем записи в свой файл партии, `python3 pipeline/ingest/review.py`
   (сухой прогон) → отказов нет → `--write`.
6. Семантический diff базы к HEAD: состав сделок, число профилей и
   `match_keys` обязаны не двинуться.
7. `python3 -m pytest -q` — зелёным.
8. `git pull --rebase origin main` → коммит по-русски → `git push`.

## Конфликт в `deals_promoted.json` — рецепт, а не ручной разбор

Четыре потока пишут в один JSON. Если rebase дал конфликт по нему:

```
git checkout --theirs static/data/deals_promoted.json   # берём чужую, более свежую
git add static/data/deals_promoted.json
git rebase --continue
python3 pipeline/ingest/review.py --write               # свои правки лягут заново
```

`review.py` идемпотентен и правит поля точечно, поэтому повторный прогон
поверх чужой версии восстановит свою партию без потерь. Файлы `fixes/*.py`
конфликтовать не могут — они у каждого свои.

## Сначала КАРКАС карточки, потом линзы

Владелец 9 августа открыл три карточки очереди рядом с их статьями и нашёл в
каждой дефект каркаса. Наполнять «Экономиста» и «Юриста» у карточки, где
неверен тип сделки и вместо предмета лежит обрывок заголовка, — красить стены
в доме без фундамента.

Карточка притока рождается ИЗ ЗАГОЛОВКА: `guess_parties()` режет его и
раскладывает куски по полям, тип ставит классификатор. Отсюда систематически:

| что бывает | пример | как надо |
|---|---|---|
| предмет — обрывок заголовка | «бывшая лизинговая „дочка" Mercedes-Benz» | ООО «МБ РУС Финанс» |
| предмет — описание | «контролирующая „Домодедово" компания» | ООО «Перспектива» |
| предмет без содержания | «офис „Открытия"» | адрес, площадь, класс здания |
| неверный тип | «Инвестиция» у покупки 100% долей | M&A |
| сторона — кусок заголовка | «Внуково» | АО «Международный аэропорт «Внуково» |
| отрасль не поставлена | «Не определена» | подтверждённая текстом |

### Пересказ заголовка — не имя. Это главная непобеждённая ошибка

Замер в ночь на 10 августа: из 86 прочитанных карточек 2026 года каркас
остался пересказом заголовка у пяти. Карточка помечена `reviewed`, линзы
наполнены — а в поле стоит то же, что и до чтения:

| карточка | стояло | а в статье прямо сказано |
|---|---|---|
| `g692dcc6b` | покупатель «Создатели „Ситилинка"» | «Алексей Абрамов, Владислав Мангутов и Олег Карчев получили по 33,33% долей» |
| `g692dcc6b` | предмет «производитель картошки для чипсов Lay's» | «в компании „Ремтехно"» |
| `gd126ba45` | предмет «офисный комплекс» | площадь, адрес, класс здания |
| `g8f7479bd` | предмет «производственная база» | что за объект и где |
| `ge482f106` | предмет «московский фармритейлер „Диалог"» | «Диалог» |

Признак у всех один: значение отвечает на вопрос «про что новость», а не
«как это называется». Родовое слово плюс уточнение («производитель того-то»,
«создатели такого-то», «дочка такой-то») — это ПЕРЕСКАЗ, и он попадает на
экран в плашку сторон и в заголовок карточки.

Проверка на одну секунду: можно ли по этому значению найти компанию в ЕГРЮЛ
или узнать её на вывеске? «Ремтехно» — да, «производитель картошки для чипсов
Lay's» — нет. Если имя в статье есть — оно и идёт в поле, а описание уходит в
`eco.share` или `eco.context`, где оно к месту. Если имени в статье НЕТ —
тогда родовое описание честно, но для недвижимости вместо него берутся
характеристики (площадь, адрес, класс), а не слово «комплекс».

ПРОВЕРЯЙТЕ В ЭТОМ ПОРЯДКЕ:

1. **Тип сделки.** Их ровно пять: M&A, Инвестиция, IPO, Продажа с торгов,
   Финансирование · структурная сделка. 100% долей или контрольный пакет —
   M&A. «Инвестиция» — раунд или миноритарная доля без контроля. Тип решает
   ПОДПИСЬ В ПЛАШКЕ СТОРОН: при «Инвестиции» покупатель называется
   «Инвестор». `review.py` умеет править поле `type`.
2. **Предмет** — название компании или объекта, а не описание.
3. **Стороны** — юрлица или узнаваемые бренды целиком, в именительном падеже,
   в ёлочках «», а не в прямых кавычках "".
4. **Отрасль** — подтверждённая текстом.
5. И только потом eco/law.

НЕПРОЧИТАННАЯ КАРТОЧКА БОЛЬШЕ НЕ ВЫХОДИТ ПО МОЛЧАНИЮ. `approve.py` не
публикует карточку без отметки `reviewed`, даже если сутки молчания истекли:
раньше молчание выпускало её КАК ЕСТЬ, то есть ровно в том виде, в каком её
собрал разбор заголовка. Решение человека кнопкой по-прежнему сильнее.

## Что искать в статье

Порядок — от самого ценного к менее:

1. **Договорные условия** (просьба владельца, самая пустая линза — 0,9% у
   непрочитанных): заверения об обстоятельствах, возмещение потерь
   (индемнити), ограничение ответственности, отлагательные условия, опционы и
   обратный выкуп, отложенный платёж (earn-out), эскроу, неконкуренция,
   обязательство сохранить бренд и команду. → `law.terms`, `law.struct`.
   Полный перечень — раздел CLAUDE.md «Что искать для линзы „Юрист"».
2. **Согласования** — `law.appr`, даже если ответ отрицательный
   («разрешение правительства не получено» — тоже про согласования).
3. **Показатели предмета** (выручка, прибыль, капитал) → `eco.target_fin`.
4. **Оценки экспертов с именами** → `eco.val`. В `sum` они не идут.
5. **Кто владел активом до сделки** → `eco.context`.
6. **Цель сделки** — прямой речью покупателя, если есть → `eco.rationale`.
7. **Предмет и доля** → `eco.share`.

## Когда одного источника мало — ищите второй

Замер 10 августа по 504 прочитанным карточкам: источник ровно один у 80%, и
ПОСЛЕ честного чтения линза «Юрист» остаётся пустой у 56%, а обе линзы бедны
у 29%. Это не лень чтения — это потолок одного источника: обычная заметка о
сделке не пишет ни о заверениях, ни об индемнити, ни о согласованиях.

ПОРОГ, ПО КОТОРОМУ ИДТИ В ПОИСК (не по всем карточкам, а по этой трети):
статью прочитали, факты перенесли — и всё равно пусты И `law.*`, И
`eco.val`/`eco.target_fin`. Тогда:

1. `WebSearch` по сторонам и предмету сделки. Ищем ВТОРУЮ статью о ТОЙ ЖЕ
   сделке, а не любую статью про эти компании.
2. Убедиться, что статья про ЭТУ сделку. Заголовок говорит об этой сделке, а
   текст — обо всей истории актива: «в 2011 году выкупил у Батуриной» — это
   другая сделка того же объекта. Проверять по дате, сторонам и предмету
   разом, а не по одному совпадению имени.
3. `python3 pipeline/ingest/fetch_article_texts.py <адрес> --write` — забрать
   текст в кэш. Без этого шага цитату не подтвердить, и `review.py` откажет.
   ЭТО ОБЯЗАТЕЛЬНО ДАЖЕ ЕСЛИ ВЫ УЖЕ ПРОЧИТАЛИ СТРАНИЦУ ЧЕРЕЗ WebFetch:
   поисковая выдача помнит страницы, которых на сайте уже нет (по «36,6» и
   «ЛекОптТоргу» выдача вернула адрес, отвечающий 404), а пересказ
   инструмента — не дословный текст.
4. Дописать адрес в `src` через `review.py` (поле аддитивное) и оттуда же
   брать цитаты для полей.

ЧЕГО НЕ ДЕЛАТЬ. Не подставлять «статью про ту же компанию» вместо статьи про
сделку: рабочая ссылка на чужую страницу хуже видимого 404 — две мёртвые
ссылки однажды «починились» ссылками на Википедию, и одна из них вела на
статью «Нью-Йоркская фондовая биржа». Не переносить в поля подробности,
которых нет дословно в скачанном тексте: внешний поиск отдаёт правдоподобный
пересказ, и он не годится (по «Yadro» так пришли номер ООО и имя гендиректора,
не подтверждённые ничем). Ничего не нашлось — это честный исход, карточка
остаётся как есть.

## Пять ошибок, которые стоили нам больше всего

- **«Цель сделки» = дословная копия «Дополнительной информации».** У 68%
  непрочитанных карточек. Формально поле не пусто, а читатель видит один абзац
  дважды. Сверяйте `eco.rationale` с `extra` ПЕРВЫМ делом.
- **«Не привлекался» — утверждение, а не пустота.** Стоит у 83% непрочитанных.
  У ГАП «Ресурс»/Granmulino в этом поле было «Не привлекался», а в статье —
  «советником со стороны продавца выступал инвестбанк Unicorn». Проверяйте
  каждое категорическое отрицание, а не только прочерки.
- **Имя стороны — в ИМЕНИТЕЛЬНОМ падеже.** В цитате оно почти всегда косвенное
  («купил у Автодома», «принадлежащее Виктору Маршеву»). Проверка дословности
  падеж не различает; `name_is_nominative` отказывает — исправьте форму.
  И не пишите родовое описание вместо имени («Семья бизнесмена Говора» вместо
  ООО «Кузбасский деловой союз»).
- **Число из подзаголовка — не сумма сделки.** Если тело статьи говорит
  «стоимость не раскрывается», а подзаголовок называет цифру, в `sum` не идёт
  ничего; оценки — в `eco.val`, с именами оценщиков.
- **Владелец без слова «продал» — не продавец.** «Основательница сети» и
  «принадлежит X» → `eco.context`, а не `seller`. Нужна фраза, называющая роль
  прямо и относящаяся ко времени сделки.

## Границы

- Значение на экране начинается с ЗАГЛАВНОЙ буквы: обрезая начало предложения,
  поставьте её (проверка дословности регистр не различает).
- Одна запись на одно поле одной карточки. Если поле уже правили — правки
  СЛИВАЮТСЯ в одну: `old` = состояние до этого прогона, `new` = итог.
  Исключение — `src`, он аддитивный.
- Бедный источник — `python3 pipeline/ingest/review.py <id> --mark-read --write`.
  Это честный исход, а не поражение.
- Не трогать: `pending.json`, `moderation_state.json`, `telegram_posts`,
  ветку `claude/kompas-cards-ux-wwn5cs`. Не создавать pull request, не делать
  `push --force`.

## Когда остановиться

Своя очередь пуста (замерьте, а не на глаз) — короткий отчёт и стоп. Не
переходите на чужой год: там работает другой поток.
