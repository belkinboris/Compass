# Рутина «публикация» — порядок работы

Ежечасно в :05, 10:00–21:00 МСК. Задача одного прогона: применить решения
владельца и партнёров из Telegram-консоли, принять карточки перед первым
постом и отправить или обновить посты в канале.

Этот файл — единственный источник порядка работы. Если он расходится с тем,
что вы помните из прошлых прогонов этой сессии, прав файл. Прежний текст
запуска — `routines/launch_texts_2026_09_24.md`.

## Что читать и когда

- **Всегда:** CLAUDE.md и этот файл.
- **Есть решения из консоли или карточки без штампа приёмки** —
  `docs/moderation.md` (как решения доходят до базы, что значит молчание)
  и `docs/card_acceptance.md` с `pipeline/ingest/CARD_ACCEPTANCE_BRIEF.md`.
- **Вычитка задержала пост** — `pipeline/publish/check_post.py` (докстрока
  объясняет каждое правило) и `python3 pipeline/docs_budget.py --find
  "<симптом>"`.
- **Правка формата поста** — докстрока `render()` в
  `pipeline/publish/format_post.py`: состав поста там и записан.

## Сбои и отчёт

**Любой сбой — сразу PushNotification**, одна строка до 200 знаков: git push
не проходит после повтора; `TELEGRAM_BOT_TOKEN`/`MODERATION_TOKEN` не заданы
там, где раньше были; необработанное исключение; `send_telegram.py` упал по
сети (ответ похож на блокировку контейнера или прокси — дословный текст
ошибки).

**Отчёт в консоль — последним шагом, всегда, даже если пусто:**

    python3 pipeline/ops_status.py публикация --posted <постов> --edited <обновлено> --applied <применено решений> --soon <N> --unread <N> --held <N>
    python3 pipeline/ops_status.py публикация --nothing --soon <N> --unread <N> --held <N>
    python3 pipeline/ops_status.py публикация --broken "коротко и по-человечески, что не сработало"

Числа `--soon/--unread/--held` — из `static/data/pending.json` тремя
группами: `held: true` — придержанные (`--held`); из остальных — с
`reviewed` и `accepted` выйдет по молчанию (`--soon`); без `reviewed` не
публикуется по молчанию никогда (`--unread` — назвать обязательно, чинить
это не ваша задача, это шаг притока). Свой текст не пишите, внутренних слов
не используйте («очередь решений», «pending», «предпросмотр», «G7»,
«reviewed») — скрипт их отклоняет. Кнопки «что скоро выйдет», «что ждёт
прочтения», «что придержано» скрипт добавит сам.

## Главное: подтверждение сайту — только после git push

`approve.py` — два отдельных шага. `--write` применяет решения только
локально и сайту ничего не подтверждает; `--consume` говорит сайту
«применено» и вызывается последним, после успешного push. 17 августа
решение по Wegosty потерялось именно так: сайт уже считал его применённым,
а контейнер умер до push. Если `--consume` в прогоне не вызвался — не
страшно: `decided_raw` в `moderation_state.json` не даст применить решение
повторно, просто вызовите `--consume` в следующем прогоне.

## Порядок

1. `git pull origin main`. Папки `pipeline/ingest` нет — сначала
   `git clone https://github.com/belkinboris/Compass.git .`. `git push`
   отказывает авторизацией — `add_repo(owner="belkinboris", repo="Compass",
   access="push")` и повтор; не помогло — PushNotification.
2. `python3 pipeline/ingest/approve.py` (сухой прогон) — решения с сайта
   (`/api/moderation/decisions`, токен `MODERATION_TOKEN` /
   `TELEGRAM_WEBHOOK_SECRET`) и карточки с истёкшими сутками молчания.
   Токена нет — PushNotification и строка в отчёте. Сайт отвечает не 200 —
   одна строка в отчёте, что решения сегодня недоступны.
3. Есть что применить — `python3 pipeline/ingest/approve.py --write`.
4. **Приёмка.** Карточки, рождённые кнопкой «в работу», и карточки базы,
   которым предстоит первый пост, без штампа `accepted`:
   `python3 pipeline/ingest/accept_card.py --queue` → чтение по брифу →
   `--check` → `--apply <ответ> --write`. Без штампа первый пост не уйдёт.
5. **Вычитка новых карточек до постов:** `python3 pipeline/proofread.py
   --queue` — обычно ровно те, что только что перешли из консоли в базу
   (чаще всего список пуст). До 10 карточек за прогон: саб-агент с
   «Правилами для редактора» из `pipeline/PROOFREADING_ROUTINE.md`, файл
   `data/inbox/proofread/<дата>-pub.json`, `--check`, один раунд
   переделки, `--write`; карточка без правок — `--mark-clean`.
6. `python3 pipeline/publish/send_telegram.py` (сухой прогон). Он вычитывает
   посты перед отправкой (`check_post.py`): «Вычитка задержала постов: N» —
   не сбой, а сработавшая защита; назовите их в отчёте.
7. Есть что отправить — `python3 pipeline/publish/send_telegram.py --write`.
8. `python3 pipeline/send_access_requests.py --write` — заявки на доступ,
   которые сайт не смог сам донести до консоли (сбой уведомления
   регистрацию не роняет, и заявка может лежать молча).
9. Карточки менялись — `python3 pipeline/facts_derive.py --write`, полный
   `python3 -m pytest -q` зелёным, семантический diff к HEAD. Применялись
   только решения по сырью — `moderation_state.json` всё равно изменился,
   его тоже в коммит.
10. `git pull origin main`, коммит по-русски, `git push -u origin main`.
    Отклонён — `git pull --rebase origin main`, один повтор.
11. **Push успешен — только теперь** `python3 pipeline/ingest/approve.py
    --consume`. Не прошёл даже после повтора — `--consume` не вызывать,
    сказать в отчёте и PushNotification.
12. Применились решения или ушли посты — запись в журнал PRODUCT_ROADMAP.md.
13. **Отчёт в консоль** (формат выше).

## Чего не делать

- Не запускать fetch/triage/enrich/draft/promote/review/send_drafts — это
  шаги притока.
- Не трогать ветку `claude/kompas-cards-ux-wwn5cs`; не создавать pull
  request; не переписывать историю git; не делать `push --force`.
- Не менять правила «молчание сутки — публикуем», «сырьё по молчанию не
  публикуется», «выкинуть сильнее таймаута».

Контейнер поднимается пустым — зависимости ставит
`.claude/hooks/session-start.sh`.
