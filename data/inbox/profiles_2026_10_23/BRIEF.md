# Профили для сторон сделок без профиля — задание на пачку (23 октября 2026)

Владелец: «Конечно нужно всем профили заводить, нам же нужно показывать их фин
показатели если люди кликнут, а значит нужно им инн присваивать».

В базе 934 строки-стороны (продавец, покупатель, предмет), записанные текстом
без профиля компании. Тебе дана одна пачка: `batchN.json` — список
`{text, mentions:[{deal, role, title, date, buyer, seller, target, src}]}`.

**Ты НИЧЕГО не пишешь в базу и в `pipeline/fns_registry.py`.** Твой результат —
один файл `data/inbox/profiles_2026_10_23/batchN.result.json` (список, по
записи на каждую строку пачки, порядок тот же). Применит его одна сессия
одним скриптом.

## Прочитать перед работой
- `docs/company_profiles.md` — разделы «Имя профиля — компания, а не предмет
  сделки», «Близнецы», «Отрасль профиля», «Описание профиля (`desc`)».
- `docs/company_data.md` — «ФНС: квоты и порядок поиска ИНН», «Банки: ИНН и профиль».
- Список отраслей сайта — значения `ind` у существующих профилей в
  `static/data/deals_promoted.json` (бери только из них).

## Что решить по каждой строке (поле `kind`)
- `ru_company` — российское юрлицо или бренд российской компании. Нужен ИНН.
- `foreign_company` — иностранная компания (ИНН нет; профиль без финансов).
- `existing` — профиль этой компании УЖЕ есть в базе под другим написанием
  (проверь `companies` по имени, транслитерации, бренду/юрлицу) — укажи `existing_id`.
- `person` — человек или несколько людей. Профиль не заводится.
- `not_company` — описание, а не компания: доля, здание, «российский бизнес X»,
  «структуры, связанные с …», «менеджмент», регион, «все активы фонда»,
  перечень нескольких сторон через запятую. Если внутри названа ОДНА
  конкретная компания, которая и есть сторона (например «сеть клиник DocMed
  (ООО «Докдети Холдинг»)»), — это `ru_company`/`existing` с этой компанией, а
  описание уходит в `desc`. Если сторон несколько — `not_company` с пояснением.
- `state` — государство, госорган, регион.

## ИНН (только для `ru_company`)
`egrul.nalog.ru` из этой среды недоступен. Рабочий путь — datanewton.ru:
- поиск: `https://datanewton.ru/search?query=<имя>` (curl с `-A "Mozilla/5.0"`);
- карточка юрлица и история участников:
  `https://datanewton.ru/contragents/<ОГРН>/history/timeline`.
Лучший путь для продавца — **история участников предмета сделки**: если у
предмета есть ИНН/ОГРН (в `pipeline/fns_registry.py` или в источниках
карточки), прежний участник в его истории назван с ИНН — это механическое
доказательство. Иначе — поиск по имени, и тогда ИНН ставится, только если
юрлицо одно и совпадает с фактами из карточки (регион, ОКВЭД, даты,
действующее/ликвидировано к дате сделки). Тёзки — обычное дело («ПАО МАГНИТ»
встречалось с двумя ИНН). Не уверен — `inn: null` и `inn_note` с тем, что
проверил. Пустое поле честнее правдоподобного.
Бренд группы («Северсталь», «Ареал») — головная компания группы, не
операционная дочка (см. `docs/company_data.md`).

## Формат записи результата
```json
{"text": "<как в пачке>", "kind": "ru_company",
 "existing_id": null,
 "name": "Металлстандарт",              // как называют в деловой речи, им. падеж
 "legal_name": "ООО «Металлстандарт»",
 "inn": "7702845361", "ogrn": "…",
 "inn_source": "https://datanewton.ru/contragents/<ОГРН>/history/timeline",
 "inn_note": "что проверено: регион, ОКВЭД, почему не тёзка",
 "ind": "ГМК и добыча",
 "desc": "Одно-два предложения: чем занимается компания, где. Юрлицо — ООО «…».",
 "note": "для not_company/person — коротко почему"}
```
`desc` — по правилам `docs/company_profiles.md#описание-профиля-desc`: что за
компания, а не пересказ сделки; без выдумок — только то, что видно в реестре
и источниках карточки. Нет сведений — короткое «Юрлицо — ООО «…», г. …,
основной вид деятельности по ЕГРЮЛ — …».

Язык — по правилам CLAUDE.md «Язык для людей» (desc читают посетители сайта).
В конце ответа — сводка по `kind` и сколько ИНН найдено.
