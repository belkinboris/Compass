# КОМПАС

Платформа о сделках, компаниях и консультантах российского рынка. Карточки собираются из публичных источников, объединяют новости об одной сделке в единый жизненный цикл и показывают сведения через две профессиональные линзы: «Экономист» и «Юрист».

## Что уже работает

- лента сделок с поиском, фильтрами и ссылками на готовые подборки;
- карточки сделок со сторонами, предметом, суммой, структурой, согласованиями, консультантами и источниками;
- этапы сделки: переговоры, подписание, согласование, закрытие или срыв;
- профили компаний и консультантов, отраслевая аналитика;
- ИИ-ассистент по базе и, при настройке, по свежей выдаче Яндекса;
- вход по одноразовой ссылке, подписки, комментарии и обращения в редакцию;
- пайплайн сбора, классификации, дедупликации, обогащения и ручного допуска новых карточек.

Данные могут быть неполными или содержать ошибки: платформа не достраивает неизвестные факты догадками и сохраняет ссылки на первоисточники.

## Локальный запуск

```bash
pip install -r requirements.txt
uvicorn main:app --reload
# http://127.0.0.1:8000
```

Тесты:

```bash
python3 -m pytest -q
```

## Переменные окружения для production

Обязательные для полноценного запуска:

- `DATABASE_URL` — PostgreSQL; без неё используется локальная SQLite;
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` — отправка ссылок для входа;
- `COOKIE_SECURE=true` — secure-cookie на HTTPS.

Для ИИ-ассистента и веб-поиска:

- `YANDEX_API_KEY`;
- `YANDEX_FOLDER_ID`;
- опционально `YANDEX_MODEL`, параметры поиска из `yandex_search.py`.

Без ключей ИИ фронтенд и база продолжают работать, а ассистент возвращает локальный fallback.

## Где лежат данные

- `static/index.html` — интерфейс и небольшая группа кураторских карточек;
- `static/data/deals_promoted.json` — основная браузерная база сделок и компаний;
- `static/data/bulk_deals.json` — компактные записи;
- `db/models.py` — нормализованная SQL-схема, аккаунты, подписки, комментарии и редакционные обращения;
- `pipeline/ingest/` — регулярный приток новых публикаций и обновлений существующих сделок.

Сделки пока читаются фронтендом из JSON. SQL-схема уже существует, но переход к единому каноническому хранилищу остаётся задачей до масштабирования.

## Обновление одной и той же сделки

`pipeline/ingest/match.py` ищет существующую карточку. Если новость относится к ней, `pipeline/ingest/enrich.py`:

- добавляет новый источник;
- заполняет только подтверждённые пустые поля;
- двигает статус только вперёд;
- добавляет этап в `events`;
- не перезаписывает конфликтующий факт автоматически.

Новая самостоятельная карточка проходит через `pipeline/ingest/promote.py`. Автоматическая публикация новых карточек сейчас намеренно отключена флагом `NEW_CARDS_NEED_REVIEW`: первый прогон на живом потоке показал высокий риск ложных срабатываний классификатора.

Ручные миграции должны быть воспроизводимыми. Для текущих кураторских исправлений используются:

```bash
python3 pipeline/fix_curated_cards.py --write
python3 pipeline/merge_deal_histories.py --write
```

## Деплой

Проект запускается через `Procfile`. Перед публичным запуском необходимо:

1. подключить постоянный PostgreSQL и SMTP;
2. применить миграцию данных в SQL либо зафиксировать резервное копирование JSON и БД;
3. настроить мониторинг ошибок, логирование и резервные копии;
4. включить фактическую доставку подписок;
5. подготовить административную очередь комментариев и обращений;
6. добавить правовые документы и политику обработки данных.

Подробный продуктовый и коммерческий аудит: `LAUNCH_AUDIT.md`.
